# TravelBlog

Я разработал TravelBlog как сайт для публикации историй о путешествиях, просмотра записей других пользователей и обмена впечатлениями. Интерфейс выполнен по предоставленному макету, данные загружаются из серверного API.

## Возможности

- Просмотр путешествий и детальной страницы каждой публикации.
- Регистрация, вход и выход из аккаунта.
- Создание истории с фотографией JPEG/PNG и предпросмотром перед отправкой.
- Добавление отзывов с проверкой обязательных полей и ограничением 600 символов.
- Личный кабинет, редактирование имени, города и описания, смена пароля.
- Адаптивный интерфейс для компьютеров, планшетов и телефонов.

## Технологии

React, JavaScript, Vite, React Router, TanStack Query, React Hook Form, Fetch API, SCSS, БЭМ, CSS Grid и Flexbox. Иконки подключены через SVG Sprite.

## Запуск проекта

Нужны Node.js 20.19+ или 22.12+ и npm. Вместо `REPOSITORY_URL` укажите адрес этого репозитория.

```sh
git clone REPOSITORY_URL travel-blog
cd travel-blog
npm install
npm run dev
```

Откройте локальный адрес, который выведет Vite в терминале.

```sh
npm run build
npm run preview
```

Сборка создаётся в `dist/`; `preview` позволяет посмотреть её локально.

По умолчанию используется `https://travelblog.skillbox.cc`. Для другого адреса скопируйте `.env.example` в `.env`, измените `VITE_API_BASE_URL` и перезапустите Vite. Секреты для запуска не требуются; переменные `VITE_*` доступны в браузере.

## API

Приложение работает с серверным API TravelBlog. [Документация Swagger](https://travelblog.skillbox.cc/swagger).

Загрузка записей, авторизация и сохранение данных зависят от доступности сервера. Приватные страницы требуют входа. После публикации истории или отзыва обновляется соответствующий кеш данных.

## Особенности реализации

Страницы находятся в `src/pages`, общие компоненты — в `src/components`, запросы — в `src/api`. Авторизация вынесена в Context, серверное состояние управляется TanStack Query, формы — React Hook Form. Для запросов предусмотрены состояния загрузки, ошибки и блокировка повторной отправки.

SCSS разделён на глобальные параметры и отдельные БЭМ-блоки. Стили собираются через `@use`/`@forward` и подключаются один раз в `style.scss`. На небольших экранах перестраиваются сетка карточек, формы и профиль.

SVG-спрайт содержит оригинальные иконки и контуры логотипа. Фон шапки хранится локально, фотографии публикаций приходят из API. Шрифты подключены локально: Poppins для поддерживаемых символов, Noto Sans для кириллицы. Лицензии OFL находятся в `src/assets/fonts`.

Токен хранится в `sessionStorage`, пароль не сохраняется. При HTTP 401 сессия очищается. Токен доступен JavaScript, поэтому такое хранение не защищает от XSS. При сохранении профиля запрос смены пароля отправляется только при заполненном новом пароле; результаты операций обрабатываются отдельно.

Для размещения сборки сервер должен возвращать `index.html` при переходе на клиентские маршруты, например `/profile` или `/posts/1`. Vite поддерживает это при локальном запуске.

## Известные ограничения

- API принимает фотографию профиля, но не предоставляет документированного способа получить сохранённый аватар. Выбор файла и локальное превью доступны; постоянное отображение фотографии не реализовано, сохранение самого изображения отдельно не подтверждено.
- Большие фотографии могут отклоняться сервером. Числовой предел загрузки не документирован. Доступный HTTP 413 обрабатывается отдельно; если браузер скрывает ответ из-за CORS, точный статус определить нельзя.
- Восстановление забытого пароля через email не реализовано: соответствующего документированного API нет.
- Кириллические метрики Noto Sans могут отличаться от шрифта исходного макета.
